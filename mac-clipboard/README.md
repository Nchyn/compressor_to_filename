# macOS JPEG文件剪贴板

## v0.4.1 五端口直连（当前）
默认依次绑定48731、48732、48733、48734、48735；仅端口占用时退避，不自动终止其他进程。全部占用时UI显示原因。网页依次发现，校验service标记和协议version≥3，优先重用上次地址。单个探测超时1.2秒。显式--port指定其他端口不退避，主要用于测试。GUI退出/崩溃时服务通过stdin EOF退出；正常重启等待子进程结束，防止遗留端口。需构建新版App并更新网页；验证命令为python3 -B mac-clipboard/test_ports.py（先构建App）。
客户端填写可信压缩器URL并点击“保存并重启”，网页自动访问127.0.0.1:48731，无临时令牌、配对弹窗或配对轮询。允许范围是URL的Origin（协议＋主机＋端口），不限制路径；同一来源中的所有页面均获得文件上传与剪贴板操作权限。仅添加自己信任且安全维护的网站。保留Host与Origin校验；不允许未配置的远程来源。清除允许来源可停止该网站访问。file://仍须单独允许，不推荐。网页与客户端需配套升级，浏览器可能还需允许本地网络访问。客户端不做编解码，剪贴板不写D1。

以下配对相关条目仅为旧版历史记录，v0.4.0不再使用。

## 交互客户端（旧版）
打开同目录 `JPEG Clipboard.app`。具有原生控制台与菜单栏入口；关闭窗口后后台继续运行，菜单栏可重新打开或退出。

- 服务固定监听127.0.0.1:48731。正常打开新版indexv2.html即可自动发现；首次在客户端确认来源后配对，下次自动重连，不需要点击“打开压缩器”。该按钮仅是快捷入口。
- 自定义URL用于保存快捷入口；仍需在首次配对弹窗中明确允许。授权按Origin隔离、不按路径隔离，HTTPS来源或本机HTTP来源可请求配对；未批准请求不能上传/操作剪贴板。
- file://需额外允许，所有不透明来源共享null安全来源，不建议用于长期授权；推荐HTTP(S)。
- 配对凭据由网页localStorage持有，客户端仅保存哈希；服务重启后授权仍有效。“撤销全部配对”立即使旧凭据失效，网页点击状态点可重新申请。
- 配对请求120秒过期、一次性领取凭据；不发送给编码Worker、Cloudflare或D1。撤销后也应清理浏览器站点数据以移除旧本地凭据。
- 状态区显示配对来源、最近网页心跳和文件复制；超过35秒无心跳显示未连接。浏览器可能需要允许本地网络权限；端口冲突需先关闭旧客户端。
- “打开缓存”便于检查已生成文件，不自动删除剪贴板引用文件。
- App保留Python本地服务依赖（/usr/bin/python3，需本机Command Line Tools），非完全独立运行时；本地ad-hoc签名，不是开发者公证发行版。其他架构需重新构建。
- 重建：`bash compressor_to_filename/mac-clipboard/build-app.command`。App自带网页/脚本快照，修改源码后需重建。
- 已通过Swift编译、App签名检查、配置文件检查、授权来源/令牌/拒绝未授权来源测试；尚未进行真实UI点击与企业微信端到端验收。

## 启动
双击本目录 `start.command`。现通过127.0.0.1的HTTP服务打开同一份 indexv2.html，避免file://的history/sessionStorage安全限制。经URL fragment传入随机端口及临时令牌，页面读取后移除fragment。模式旁绿点表示已连接；粘贴生成JPEG并自动复制文件，手动复制在日志说明列。重新启动后用新打开的HTTP页面授权，不继续使用旧file://标签。服务端为内联脚本添加CSP nonce，并移除该授权页面中的第三方统计脚本。

如Finder未执行，请在终端运行：
```bash
bash /Users/nchyn/Documents/DSH/compressor_to_filename/mac-clipboard/start.command
```
首次重新编译需要Xcode Command Line Tools（`xcode-select --install`，由用户安装）。已包含当前机器编译的helper，其他CPU架构可能需要删除旧二进制后重新编译。建议直接手动执行swiftc重新编译，不删除也可覆盖。

停止：启动终端Ctrl+C。它不是菜单栏App，也不是DSH内部插件；是Python标准库本地服务＋Swift NSPasteboard小工具。Python由macOS开发工具提供，缺失时需安装开发工具或调整启动脚本。

## 使用
1. 网页拖入/选择原图，或⌘V粘贴图片。
2. 默认保持原尺寸，关闭40MB减半；JPEG透明背景默认白色。
3. 极速模式首个小于20,000,000字节的JPEG即停止。质量优先最多5轮，仍未达标报错，不静默缩图。
4. 点击“复制JPEG文件”：网页传最终JPEG给本机服务；客户端仅落盘、写文件URL到NSPasteboard，不解码、不转码。
5. 企业微信中⌘V，查看图片/附件预览。不要自动发送。具体表现由目标应用决定。
6. 可直接下载JPEG；无客户端连接时仍可编码及下载。

“完成后自动写文件剪贴板”现默认开启，任务结束会覆盖原剪贴板内容；需要手动控制时取消勾选。客户端写入后回读验证文件URL，网页必须收到verified=true才显示成功。升级后需停止旧服务并重新运行start.command。所有素材都遵守40MB开关，未保留旧PNG测试素材的文件名豁免。

## 文件保留
生产缓存：`~/Library/Caches/LocalJPEGClipboard`。JPEG使用随机文件名，不原地覆盖、不自动删除，退出后仍可供粘贴。缓存上限1GB；到上限停止接收，不自动移除可能仍被引用的文件。需要清理时先完成粘贴/保存，再在Finder手动删除不需要的缓存。系统也可能清理Caches，因此它不是永久归档。

## 安全与限制
- 仅监听127.0.0.1，随机端口；Host、Origin、短期令牌验证；令牌经URL fragment进入页面后移除。
- 不暴露任意本地路径，不读取剪贴板历史，不上传外网，不发送企业微信消息。
- JPEG只检查头尾标识和字节限制，客户端按设计不解码验证图像。
- 输出必须严格小于20,000,000字节；文件上传分块落盘并计算SHA256，客户端不重新编码。
- 上传超时/取消后系统写入有可能已完成，网页会提示“未确认”，不能保证撤销已发生的剪贴板修改。
- 编码图片可能占用大量浏览器内存；Worker提升响应，不保证低内存设备成功。
- JPEG有损且不支持透明；浏览器决定JPEG编码与色度采样，文字、渐变需人工检查。
- 正式产品仍需签名、App打包、跨机器兼容与长时间稳定性测试。
